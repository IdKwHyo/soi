# Privacy data-flow audit

Audited 15 October 2026 against the application source following native release 17 (`40a265a7796e1d7f0ba1b9d89ff74b63a0cfd9f8`). This is a factual code inventory for the English/Thai notices and consent controls. It is not a legal certification. Later policy and consent files should be reviewed against this inventory when their behavior changes.

## Scope and method

Read-only inspection of the active Version C, sign-in, merchant copilot, customer menu, Worker handlers, storage adapters, migrations and build configuration. Build Router selected the focused Matt research workflow: follow facts to primary source code and document the evidence. No credentials, production records, private deployment settings or browser sessions were accessed. No external compliance package was installed. Existing tests were not rerun for this documentation-only audit. No browser network inspection was available, so hosting-injected behavior is not asserted to be absent.

## Browser storage and network inventory

The audited app source writes no first-party cookie and contains no analytics/ad SDK, tracking pixel, `sendBeacon` or session-replay integration. This does not certify what the hosting/authentication infrastructure adds outside the application bundle.

| Store/key | Purpose and lifetime visible in source |
| --- | --- |
| Local storage `soi-studio-v2-demo` | Root demo workspace; persists until replacement/reset, browser cleanup or eviction. No time-based expiry. |
| Local storage `soi-studio-v2-local` | Root full-app local fallback workspace; separate from demo and connected cloud state; no time-based expiry. |
| Local storage `soi-copilot-demo-v1` | Copilot/customer demo menu, costing and order state; reset replaces it with sample state. No time-based expiry. |
| Local storage `soi-copilot-demo-photos-v1` | Prepared demo dish photos, up to the current 1 MB store bound; demo reset clears stored photo entries. |
| Local storage `soi-language`, `soi-copilot-language` | User-selected interface language; no time-based expiry. |
| Session storage `soi-demo-entry` | Timestamp for one sign-in arrival animation; consumer removes it immediately and only accepts a recent timestamp. Not authentication or user tracking. |
| IndexedDB via Tesseract `idb-keyval` | Downloaded Thai/English OCR models using `soi-ocr-7-best-int-v1` cache-path prefix; no app-level expiry/deletion schedule. |
| Browser HTTP cache | Same-origin assets are served with `public, max-age=3600`; HTML and private API/image responses use `private, no-store`. Browser/site-data controls can clear these caches. |

Runtime browser assets, fonts, OCR files and images are served by this site; the build copies fonts and OCR assets into the output. `cdn.jsdelivr.net` is used by [`scripts/prepare-ocr-assets.mjs`](../scripts/prepare-ocr-assets.mjs) during asset preparation, not as a browser OCR dependency. Optional server Gemini requests use `generativelanguage.googleapis.com` (direct HTTP and Google AI SDK). Outbound reference links point to `foodsafety.gov`, `who.int`, and an owner-supplied, validated `food.grab.com` menu URL. Links do not establish third-party API integrations or overwrite Grab prices/checkout. Navigation may disclose ordinary browser/request information to the destination; the app sets `Referrer-Policy: strict-origin-when-cross-origin`.

Consent controls added later should distinguish essential/requested functionality from optional tracking. There is currently no optional tracker to turn on. A banner that merely dismisses itself does not establish pre-consent blocking for future scripts. New optional integrations need an audited registration/loading path, rejection behavior and revocation handling; adding one requires updating this inventory and notices.

## Retention, reset and deletion facts

- Active workspace JSON and history have capacity limits, not time-based retention promises. `worker/storage.mjs` preserves immutable records and mutation audit entries. The audit stores business ID, revision, action and timestamp; application code does not log request bodies with `console`.
- Full workspace reset replaces the active workspace with sample state. It does **not** delete historical D1 records, mutation audit entries or R2 source objects. It is not account erasure. Source download routes resolve currently referenced workspace objects, so retained historical objects after reset may no longer be accessible through the ordinary download UI.
- Clear chat empties the active workspace message array. Existing model reply/evaluation caches can still hold prior generated content until expiry/cleanup. Chat clearing is not a complete provider or archive deletion request.
- Embedding cache entries expire for reuse after seven days; generated reply/evaluation/candidate cache entries expire for reuse after one hour. Expired cache rows are physically deleted during a subsequent successful workspace save; an idle workspace has no guaranteed deletion at the expiry instant. Capacity eviction is owner-scoped. See `worker/assistant.mjs`, `worker/model.mjs`, `worker/backend.mjs`, and `worker/storage.mjs`: `cached`, `cachedMany`, `save`.
- Copilot order history is bounded to 500 orders and active queue to 80. Reaching capacity rejects additional records; this is not a scheduled retention process. No merchant account/order-history erasure route is implemented.
- Uploaded menu photos have an 80-record capacity. There is no full upload-deletion/garbage-collection UI or scheduled removal in the audited source.
- Original CSV/receipt cleanup after a failed competing write releases only demonstrably unreferenced objects. Ambiguous commits deliberately retain potentially referenced objects. This recovery cleanup is not a data-subject erasure system.
- No application export is proven to include every historical retained record, cache or R2 object. Export UI should not be described as a complete statutory data-access/export service without a separate verified implementation.

## Unverified operational and legal facts / release gaps

These must not be invented in published notices or treated as completed merely by adding a footer:

1. **Controller/operator identity:** legal entity/name, registered address, privacy contact, usable rights-request channel and any representative or DPO are unverified. The product name is not evidence of its legal operator. No email address should be inferred from unrelated personal context.
2. **Purpose-specific legal bases:** the applicable bases for merchant accounts, customer order data, optional AI processing, security records and storage have not been determined by this code audit. Optional cookie consent is not a blanket basis for all processing.
3. **Roles and merchant responsibilities:** controller/processor allocation between the site operator, participating merchant, hosting/authentication platform and model vendor requires operational/legal confirmation. An individual restaurant may collect customer information through table labels or notes even without account fields.
4. **Infrastructure/provider arrangements:** D1/R2 storage regions, backup lifecycle, access/support access, logging retention, subprocessors, contracts/DPAs, international transfer arrangements and hosting/authentication cookies are unverified. Repository bindings identify storage APIs, not contractual guarantees.
5. **Google AI arrangements:** live project tier, paid/unpaid terms, regional setup, provider retention, training/use settings, agreements and any international transfer safeguards are unverified. `ALLOW_MERCHANT_AI` is an operator configuration gate, not a user consent record. Source code cannot establish that the deployed service is currently enabled or disabled without checking safe runtime capabilities.
6. **Retention schedule and erasure:** no complete account/data-subject erasure workflow exists across D1 history, R2, caches, backups, order records and processors. Define approved retention periods and implement deletion/reconciliation and request verification before claiming those capabilities.
7. **Rights handling:** access, correction, objection, portability, restriction, consent withdrawal and deletion need an actual contact/handling process matched to applicable law. Local reset or clearing browser storage does not delete cloud or provider data.
8. **Applicability and risk review:** jurisdictional scope under Thai PDPA, GDPR/ePrivacy and EU AI Act, any AI role/risk classification, transparency duties, age/minor policy and launch obligations are not settled by this audit. No “GDPR compliant”, “EU AI Act certified” or “cannot be sued” assertion is supported.
9. **Operational verification:** browser network inspection of the hosted page/auth flow, consent pre-block/revoke behavior, real data-subject request drill, deletion reconciliation and deployed provider configuration remain separate checks. Unit tests cannot establish legal compliance or full hosted network behavior.

## Product statements supported by code

The demo is simulated; optional real Advisor is AI-assisted decision support. The owner reviews receipt fields, recipe assumptions and campaigns. Contribution estimates exclude unentered costs and are not net-profit guarantees; prep times are heuristics. Food-storage guidance is a review reminder, not a verified expiry or safety certificate. Customer ordering sends an order, not payment. No checkout, subscription billing, government-benefit eligibility verification or live Grab integration is implemented. These boundaries should remain consistent in Terms, interface copy and pitch materials.
