# Project instructions

Use Build Router to select only the skills needed for the requested change. Frontend work uses frontend-ui-engineering and apple-design for relevant motion. Functional changes use focused Matt Pocock implementation/module workflows and meaningful behavioral checks.

This is an SME restaurant commercial workflow, not a marketing template. Keep sources, assumptions and calculation exclusions visible. No invented business impact, real model connection, OCR accuracy or learned ranking claims.

Keep exact monetary calculations, immutable dataset/campaign snapshots, private business ownership and input validation authoritative on the server. Browser calculations are previews. Scope every storage operation to authenticated membership. Keep credentials out of source and client bundles.

For this review build, publish only through Sites. Do not push to GitHub or deploy to Vercel until Graphic authorizes that step. Keep the existing published Vercel app intact.

Use restrained motion and a single progressive WebGL scene. Respect reduced motion, coarse pointers and renderer failures. Keep all working controls usable while motion runs. No emojis or generic uniform card grids.

Run npm test, npm run check, npm run build and npm run validate when the changed inputs require them. Follow Sites' permitted preview/browser workflow. Report unavailable browser QA rather than substituting unapproved tooling.
